# finance — мій фін-трекер

Особистий сайт фінансів Аії + Telegram-бот. Замінює Excel «financial_plan». Користувач один — Аія.
Власниця проєкту не програмістка: пояснюй простими словами, **питай перед великими рішеннями**,
показуй, що змінилось і як перевірити.

## Головні правила
- **Жодного AI / LLM у коді.** Категорії обирає Аія сама (кнопки на сайті й у боті), банківські
  транзакції розкладаються за правилами, які вона створює.
- **Excel не чіпаємо і не імпортуємо.** Дані й планування Аія вносить сама.
- **Переказ у банку (заощадження) — не витрата**, а переказ. Переказ з картки на картку без
  призначення — теж переказ. Перекази не рахуються ні в доходах, ні у витратах.
- **Весь інтерфейс англійською** (сайт, бот, назви категорій).
- Валюти: **UAH і EUR** (доларів немає). Без значка = гривня.
- Сайт доступний тільки через Tailscale (не в публічному інтернеті).
- Секрети (токени Telegram, Monobank) — лише в `.env`, ніколи не в git.
- **Репозиторій задуманий публічним: особисті дані в git не потрапляють.** Банківські експорти (`export_*`, `*.csv`), бази, `.env` — в `.gitignore`;
  `.githooks/pre-commit` блокує коміт з такими файлами, токенами, номерами карток, IBAN і приватними хостами (увімкнути: `git config core.hooksPath .githooks`).
  Claude **ніколи не робить `git add -A` / `git add .`**: спершу `git status`, додає лише названі файли. Перед тим як знову зробити репозиторій
  публічним — вичистити з історії `export_11_11_26_902.csv` (коміт `c71e385`; потрібен force-push і `git reset --hard origin/main` на сервері).

## Стек
- Python 3 + FastAPI, база SQLite (`data/finance.db`), сторінки — HTML + CSS + трохи JS, **mobile-first**
  (головне — телефон).
- Telegram-бот: python-telegram-bot, режим polling (серверу не треба відкриватися назовні).
- Дизайн — дизайн-система Аії «природа × техніка», див. [DESIGN.md](DESIGN.md): Onest + IBM Plex Mono,
  бежевий/графітовий фон, одна акцентна (заповнена) кнопка на екран, кнопки-пігулки, світла й темна тема.
  **Палітра цієї апки перекриває акцент із DESIGN.md** (див. «Вигляд» нижче); решту беремо з DESIGN.md.
- Розробка — WSL на ноуті (`~/projects/finance`), робота — сервер Hetzner (користувач `aiia`).

## Дані (таблиці)
**База на ноуті (`data/finance.db`) — тестова.** На етапі 3 на сервері стартуємо з чистої бази
(тільки стартові категорії), ноутбучну `data/finance.db` на сервер не переносимо.

- `categories` — id, kind (`income` / `expense`), name, group (`essentials` / `fixed` / `fun`, лише витрати), archived
- `transactions` — id, date, kind (`income` / `expense` / `transfer`), category_id (**завжди є, крім переказу**), amount (ціле число в копійках / центах), currency, comment, source (`site` / `telegram` / `mono` / `agricole`),
  external_id (унікальний, щоб банк не дублювався), jar_id (переказ у банку), direction (`in` / `out`), paid_uah (поповнення €-банки, оплачене гривнями),
  counterpart (`people` / `accounts` — переказ не в банку: людям або між своїми рахунками), account_id (для `accounts`: рахунок, куди прийшли гроші).
  Переказ має РІВНО одне з: jar_id або counterpart (перевірка в базі).
- `accounts` — мої рахунки (де лежать гроші): name, mono_id (картки Mono додаються синхронізацією), archived. `inbox` — банківські рядки, що чекають на категорію: **ще не транзакції**, ніде не рахуються, поки Аія не розкладе (тоді переїжджають у `transactions`)
- `plans` — місяць (YYYY-MM), category_id, currency (UAH/EUR), amount — річний план (і для витрат, і для доходів), Аія редагує коли завгодно; немає рядка = плану немає. **Це ж і ліміт місяця для витратної категорії: окремої таблиці бюджетів немає** (2026-11-12 злито: старі ліміти перенесено в план, де плану ще не було)
- `jars` — банки/цілі: name, currency (обирається при створенні), target, opening (гроші, що вже лежать; не впливають на баланс жодного місяця), my_rate (курс, який
  Аія ставить сама, «з запасом»; лише для рядка «≈ у ₴»), quote (її цитата «навіщо я це роблю»), archived
- `rules` — для банку: pattern (текст в описі) → category_id, або переказ (`is_transfer`, `transfer` = `people` / `accounts`, `account_id` — куди) (Аія створює, коли розкладає нову операцію; `key` = pattern малими літерами, унікальний). `meta` — службове (коли востаннє читали картку)
- `quotes` — загальні мотиваційні цитати (див. нижче)

## Екрани сайту
1. **Головна (місяць):** дохід / витрати / баланс; план по категоріях смужками (від річного плану цього місяця)
   (✓ в межах, ! близько, ✗ перевищено — завжди словом або знаком, не лише кольором).
2. **Додати:** витрата / дохід / переказ у банку → кнопка категорії → сума → валюта ₴/€ → коментар → зберегти.
3. **Місяць детально:** план ↔ факт по кожній категорії + список транзакцій (редагувати, видалити з підтвердженням).
4. **Рік:** сітка 12 місяців × категорії (витрати групами зі світінням, потім доходи) + «Year total» і підсумки
   доходи / витрати / баланс. Перемикач вигляду **Plan / Actual / Difference** (одна сітка, три режими; план
   редагується прямо в клітинках лише в Plan) і перемикач ₴ / €. Швидко: поле «All months» заповнює рядок, «Copy from
   last year». Різниця словом/знаком (✓ ! ✗), для майбутніх місяців — порожньо. **План = ліміт:** смужки й півколо на Home та прогноз в Analytics рахуються від планової суми
   витратних категорій місяця; екрана Budgets і пункту меню більше немає (`/budgets` веде на Рік).
4b. **Analytics** (окрема сторінка, перемикачі ₴ / € та місяць / рік): див. етап 4b.
5. **Банки / Jars:** на Home — «In jars» (скільки зараз лежить у всіх банках) і «Free» (див. нижче), окремо ₴ і €; невелика картка Jars. Поповнення €-банки з гривень (`paid in ₴`) віднімає ₴ від вільних гривень. Банка: прогрес до цілі, сума у валюті банки, курс Аії, цитата; поповнити / зняти (= переказ).
6. **Налаштування:** категорії, правила банку, цитати.

**Гроші зараз (Home → «All money», «In jars», «Free»; 2026-11-13):** у Settings → Money Аія вказує, скільки було на дату (₴, €) і свій курс (₴ за €, вводить сама; курс дає лише рядок «Together ≈ … ₴», ніде не конвертуємо). Логіка (`app/wealth.py`, одне місце для Home, бота й Year), окремо ₴ і €:
- **Надіслано людям = витрата, отримано від людей = дохід**; перекази між своїми картками / рахунками й у банки — ні те, ні інше.
- `Income` = доходи + отримано від людей; `Expenses` = витрати + надіслано людям (тому Expenses може бути більшим за суму категорій).
- `All money` = старт + Income − Expenses (від дати старту); `In jars` = залишки всіх банок (opening + поповнення − зняття, і архівних); **`Free` = All money − In jars** (гроші, що не в банках, але є). Balance не показуємо ніде (ні на Home, ні в боті).
- Дата розрахунку: для поточного місяця — сьогодні, для минулого — кінець того місяця, для майбутнього — сьогодні; до дати старту або без старту All money / Free = «—».
- Бот `/month`: Income, Expenses, In jars, Free. Дані: `meta` (`start_date`, `start_UAH`, `start_EUR`, `rate`).

**Спільний доступ (партнерка):** сайт без паролів; `tailscale serve` передає акаунт Tailscale у заголовку `Tailscale-User-Login`. `OWNER_LOGIN` у `.env` (акаунт(и) власниці через кому): власниця бачить усе; будь-хто інший = viewer і бачить **лише `/jars` зі спільними банками** (галочка `Shared` у формі банки, `jars.shared`), без кнопок змін; решта → 403. Без `OWNER_LOGIN` обмежень немає. Запит без акаунта: власник, лише якщо він не через проксі (відкрито на самому сервері, як `update.sh`). Перевірка: сторінка `/whoami` показує, чий акаунт бачить сервер. Код: `app/access.py`. Перед тим як давати доступ — перевірити `/whoami` на обох телефонах.

**Приховані блоки (2026-11-13):** з інтерфейсу прибрано (але дані, розрахунки й сторінки лишились) — Home: картку Balance, «Sent to people / Received from people», блок Recent; Analytics: порівняння «this month so far» (Expenses/Income), діаграми Expenses/Income by month, Forecast. Список — `HIDDEN_BLOCKS` в `app/ui.py`; щоб блок повернути, прибрати його назву зі списку. Без Balance чотири картки Income / Expenses / In jars / Free йдуть одним рядом (`grid-4`). `deploy/update.sh <гілка>` викладає гілку на сервер для перегляду, `update.sh` без аргументу повертає main.

**Analytics → «Where the money goes» (2026-11-13):** три стовпці груп — неонова рамка (світіння як скрізь), без заливки; після тапу категорії групи — заливка **евкаліпт / море / роза** (`--fill-essentials / -fixed / -fun`, свої для світлої й темної теми) з м'яким світінням. Назви категорій лежать горизонтально в боксі фіксованої висоти (всі бари на одній лінії, усі категорії в одному ряду, довгі слова діляться по складах — фільтр `breakable`). Income / Expenses на Home: цифри зелені / червоні (`--income`, `--expense`), блок без заливки.

**Таби (2026-11-13):** Settings (Expenses | Income | Accounts | Rules | Quotes | Money), **Home** (Overview | Categories | Jars; Accounts — на пункті «рахунки») і **Analytics** (Where the money goes | Plan vs actual). Перемикачі місяця / року й ₴/€ стоять над табами й діють на всі. Активний таб — в адресі (`#categories`); Home і Analytics (`data-tabs-key`) ще й запам'ятовують останній таб у браузері, а стрілки місяця й Month/Year зберігають його (`data-carry-tab`). Settings не запам'ятовує (після помилки сервер сам обирає таб). Без JavaScript усі блоки йдуть підряд. Скрипт — `setupTabs` в `app/static/app.js`.

**Year, таблиця (2026-11-13):** фіксована сітка (`table-layout: fixed`): колонка Category прилипає зліва, фіксованої ширини (104 px телефон / 170 px комп'ютер), непрозорий фон; довгі назви обрізаються «…» (повна в `title`); усі місяці по 68 px, усі рядки по 44 px; колонка «All» ховається разом зі своїм `<col>` у режимах Actual / Difference (інакше всі стовпці зсуваються на один). При відкритті поточного року таблиця гортається до поточного місяця й підсвічує його (`yr-now`); в іншому році — з початку.

**Year → «Left at end» (2026-11-13):** рядок під таблицею (в усіх режимах) — скільки грошей лишається **на кінець кожного місяця**, окремо ₴ і €: All money того дня (старт + Income − Expenses, банки входять). До поточного місяця (включно) — факт, далі — за планом (`≈`, курсивом): попереднє число + запланований дохід − запланована витрата; місяць без плану тримає число. Ланцюжок іде через роки (січень = кінець грудня минулого року). До дати старту — «—»; без старту — підказка про Settings → Money. Колонка «Year» = грудень. Числа цього рядка **округлюються вниз до сотень** (12 345,67 → 12 300; мінус теж вниз: −50 → −100; фільтр `floor100`, лише показ). Під числом — дрібніше «≈ N ₴»: усе разом, євро за курсом Аії (Settings → Money), як «Together ≈» на Home; лише коли є курс і євро. Код: `wealth.left_at_month_end` (`together` у кожному місяці).

## Telegram-бот
- Відповідає **тільки** chat id Аії з `.env`, усім іншим — мовчить.

## Monobank
- Особистий токен з api.monobank.ua (у `.env`). Виписка — запитом раз на ~10 хв (cron):
  максимум 31 день за запит, не частіше 1 запиту на 60 с. Webhook не використовуємо (сайт не публічний).
- Нова транзакція: є правило → категорія автоматично; немає → «нерозкладені» на головній і в боті,
  Аія обирає категорію кнопкою, бот пропонує запам'ятати правило.
- Переказ між своїми картками / без призначення → `transfer`.
- Дублікати відсікаються за `external_id`.

**Зроблено (етап 7):** `python -m monosync` (cron кожні 10 хв, `flock`), `app/mono.py`, `app/rules.py`, `app/transfers.py`. З 1-го числа місяця першого запуску; картки задає `MONOBANK_ACCOUNTS` у `.env` (для кожної створюється рахунок у «My accounts»). Нові рядки спершу йдуть у `inbox` (не рахуються), правило розкладає їх одразу. Варіанти розкладання: категорія · **Sent to people / Received from people** (окремі рядки на Home і в `/month`; віднімаються / додаються до «Free», в доходи й витрати не входять) · **Between my accounts** (для витрати вказується рахунок, куди пішли гроші; для доходу — рахунок картки автоматично). Однакова сума з однієї картки на іншу (різні рахунки, ±1 день) → автоматично «Between my accounts». У боті: повідомлення з кнопками категорій + People + Accounts + «Skip, later on site», потім «Remember?»; `/sort` — по одному; понад 5 нових — одне зведення. **Банки Mono (2026-11-12):** кожна банка Mono автоматично стає банкою сайту (`jars.mono_id`; назва, ціль, «opening» = баланс на момент першого бачення; банка сайту з тією ж назвою й валютою просто зв'язується). Далі виписка банки (id банки як рахунок) дає поповнення / зняття: рядок банки зіставляється з рядком картки в `inbox` (та сама сума й валюта, ±1 день) → рядок картки стає переказом у банку (`jar_id`, `direction`), рахується один раз; без пари (відсотки, гроші ззовні) → окремий переказ. Виписка банки читається лише коли змінився її баланс. Нові банки не спільні (`Shared` — вручну). Назва / ціль після створення живуть на сайті, з Mono не синхронізуються. Категорія «Home | Decor» (речі для дому) створюється в Settings.

## Агріколь
Мало транзакцій. Завантаження виписки файлом раз на місяць — формат з'ясувати на зразку від Аії.

## Етапи (по одному, після кожного — показати Аії й дочекатися «ок»)
0. Проєкт у `~/projects/finance`, git, `.gitignore` (`.env`, `data/`), README англійською.
1. База + категорії + додавання й список транзакцій на сайті.
1b. Переробка вигляду: палітра, групи категорій, калькулятор суми, телефон як апка, комп як дашборд.
2. Головна (місяць) + бюджети.
3. **Викладка на сервер:** Tailscale на сервері й телефоні, systemd-сервіс `finance`, щоденна
   копія бази в `~/backups/finance` (зберігати 30 днів). Інструкція покроково.
4. Річний план (план ↔ реальність).
4b. **Аналітика** — окрема сторінка Analytics, з перемикачем ₴ / € і місяць / рік:
   - **Куди йдуть гроші:** частка Essentials / Fixed / Fun у % і всі категорії витрат у % — горизонтальна
     бар-діаграма, від більшої до меншої, кольори груп.
   - **Динаміка:** цей місяць проти минулого (різниця в сумі і %) і тренд за рік по місяцях — окремо витрати
     й окремо доходи.
   - **План ↔ факт:** графік по місяцях року (план лінією або тінню, факт стовпцями).
   - **Прогноз до кінця місяця:** скільки буде витрачено при поточному темпі, і порівняння з бюджетом.
   - **Без бібліотек-монстрів:** легкий SVG (малюємо самі) або маленька бібліотека — на сервері мало пам'яті.
5. Банки + перекази + цитати + екран «Налаштування» (категорії, цитати; правила банку — на етапі 7).
6. Telegram-бот.
7. Monobank: імпорт, правила, перекази.
8. Агріколь: завантаження виписки.
